# 시작하기

설치부터 첫 메시지 왕복까지의 단계별 안내입니다. 기기가 어떤 환경인지(ROOT_ADB 인지
NON_ROOT 인지)에 따라 경로가 갈리므로, 먼저 본인 케이스를 정하고 해당 절만 따라오면 됩니다.

## 1단계 — 앱 설치

1. 최신 `app-debug.apk`(또는 릴리스 APK)를 기기에 설치해 실행합니다.
2. 상태 탭 상단에서 모드를 고릅니다. 자동 감지에 맡겨도 되지만, 직접 지정하면
   화면 구성이 그 모드에 맞게 고정됩니다.
   - 일반 스마트폰 ⇒ **NON_ROOT**
   - 루팅 기기·redroid·시뮬레이터 ⇒ **ROOT_ADB**
3. 서버 포트(기본값 3000)을 확인합니다. 같은 네트워크의 다른 컴퓨터에서 접속할 계획이면
   기억해 두세요.

## 2단계 — 모드별 준비

### NON_ROOT 인 경우

화면의 안내에 따라 아래 권한을 허용합니다.

| 권한 | 왜 필요한가 | 설정 위치 |
|---|---|---|
| 알림 접근 | 알림을 읽어서 이벤트를 만들기 위해 | 설정 → 앱 → IrisGUI → 알림 접근 |
| 배터리 최적화 예외 | 절전 시 서비스가 죽는 것을 막기 위해 | 설정 → 배터리 → 최적화 예외에 IrisGUI 추가 |
| (선택) 알림 표시 | 상태 표시 알림을 위해 | 앱 알림 허용 |

이후 상태 탭의 서비스 스위치를 **켜면** 앱 안에서 서버가 뜨면서 `/ws`, `/reply`가
동작하기 시작합니다.

### ROOT_ADB 인 경우

루트 서버(app_process)를 띄워야 합니다. 기기 안에 루트 환경이 있으면 앱이 스스로
시작하므로, 보통은 그냥 서비스 스위치를 켜기만 하면 됩니다.

1. 상태 탭의 서비스 스위치를 켠다 → 켜짐으로 바꿉니다.
2. 잠시 뒤 서버 카드가 초록 "실행 중"으로 바뀌면 성공입니다 — 앱이 내부 루트 셸이나
   기기 속 adbd(127.0.0.1:5555)에 접속해 서버를 직접 기동한 것입니다.
3. 빨간색으로 바뀌었다면:
   - **[app_process 시작]** 버튼을 눌러 수동 재시도.
   - 그래도 실패하면 로그에 나온 원인(`NO_ROOT`, `NO_ADBD`, `AUTH_FAILED`, `START_TIMEOUT`)에
     따라 조치합니다. `AUTH_FAILED` 는 최초 1회 USB 디버깅 승인이 필요한 경우이고,
     `NO_ADBD` 는 `adb shell setprop persist.adb.tcp.port 5555` 로 adbd/tcp 포트 연 뒤
     재시작하면 됩니다.
   - PC adb로 직접 띄우는 것도 항상 가능한 방법입니다. PC에서:
     ```
     adb shell
     su
     CLASSPATH=$(pm path party.qwer.irisgui | sed 's/package://; s/\r//') \
       setsid app_process / party.qwer.irisgui.Main 3000 &
     ```
     마지막 숫자는 앱 화면에 적어 둔 서버 포트와 같아야 합니다.

> 포트는 상태 탭의 표시와 실제 서버 포트가 항상 같아야 정상입니다. 서버가 다른
> 포트를 쓰면 상태 화면이 "실행 중"을 못 찾고 "실행 안 됨"으로 보입니다.

### HAYUL 인 경우

HayulGUI 패치가 적용된 기기에서는 앱이 자동으로 해당 모드를 감지하며, 별도 루트
설정 없이 서버가 앱 안에서 전부 기동됩니다. ROOT_ADB와 기능이 동일합니다.

## 3단계 — 정상 작동 확인

PC의 터미널에서(기기와 같은 네트워크라고 가정):

```
curl http://<기기 IP>:3000/process-status
```

- ROOT_ADB: JSON 응답에 `server_running: true` 가 찍히는 것을 확인.
- NON_ROOT: 이 엔드포인트는 제공되지 않습니다. 대신 `ws://<기기 IP>:3000/ws` 접속이
  성립하는지(wscat 같은 간단한 도구로) 확인합니다.

그다음 카톡으로 테스트 메시지를 보냅니다. 로그 탭(또는 상태 탭의 메시지 목록)에
 방금 들어온 문장이 뜨면 이벤트 수집이 완료된 것입니다.

## 4단계 — 첫 봇 테스트

가장 단순한 왕복 테스트입니다. 기기 안에서 확인하는 방법(스크립트 탭)과 PC에서
확인하는 방법(irispy-client) 두 가지가 있습니다.

### 기기 안에서 확인하기

1. 스크립트 탭 → 기본 생성된 `main` 프로젝트가 이미 `!hhhi` 라는 명령을 준비해 둡니다.
   [실행]을 누릅니다.
2. 임의의 카톡 방에서 `!hhhi` 를 발신합니다.
3. `hey from irisgui!` 라는 답장이 오면 전체 연결이 검증된 것입니다.

자세한 내용과 프로젝트 구조는 [스크립트 · Linux 환경](05-script-linux.md)에서 다룹니다.

### PC에서 확인하기 (irispy-client)

```
pip install irispy-client
```

아래 스크립트를 저장해 실행하면 모든 대화방의 메시지가 터미널에 출력됩니다.

```python
from iris.bot import Bot

bot = Bot("http://<기기 IP>:3000")

@bot.on_event("message")
def on_message(ctx):
    print(f"[{ctx.room}] {ctx.sender}: {ctx.message}")

if __name__ == "__main__":
    bot.run()
```

정상 출력되면 답장까지 포함한 봇 개발 단계로 넘어가면 됩니다 —
자세한 내용은 [외부 클라이언트 개발](04-external-client.md) 참고.

## 자주 만나는 오류

| 증상 | 원인 • 해결 |
|---|---|
| 상태 탭이 계속 "실행 안 됨" | 앱이 보는 서버 포트≠서버 실제 포트. 양쪽 포트를 맞추고 재시작 |
| `/ws` 접속 후 응답 없음 (NON_ROOT) | 서비스 스위치 꺼짐 또는 알림 접근 미허용 |
| 이벤트가 안 옴 (ROOT_ADB) | 서버 기동 여부 먼저 확인. 그다음 카톡 DB 접근(루트 확인), bot_id 감지 실패 여부(로그 탭) |
| 답장은 오는데 이벤트가 안 옴 | 내 메시지 전송은 브로드캐스트에서 제외되는 것이 정상(`SYNCMSG` 계통) |
| connection refused | 기기와 클라이언트의 네트워크 분리. 같은 Wi-Fi/네트워크 세그먼트인지 확인 |
